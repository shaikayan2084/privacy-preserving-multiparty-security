The Problem

Why Privacy Matters in Collaboration

Organizations need to collaborate on sensitive data — but sharing raw information creates serious privacy and security risks.

Consider hospitals wanting to jointly study disease patterns, or banks detecting fraud by pooling transaction data. In both cases, the raw data is confidential and cannot simply be shared.

Traditional approaches force a painful choice: either share sensitive data and risk privacy violations, or work in isolation and lose the benefits of collaboration. SMPC breaks this trade-off entirely.

"Cloud computing must decrypt data to process it — creating a window of exposure. SMPC eliminates this window entirely by computing on cryptographic shares."

— Ravi Chandra Thota, IRJMETS Vol.07/Issue:10 (Oct 2025)

🔓 Traditional Encryption Fails Here

Encryption protects data at rest and in transit — but the moment data needs to be processed, it must be decrypted. This creates a vulnerability window where insider threats or breaches can expose raw data.

🏥 Healthcare Example

Three hospitals want the most effective treatment across 50,000 combined patient records. Sharing records directly violates HIPAA. SMPC computes the answer — no hospital ever sees another's records.

💳 Finance Example

Five banks want to jointly train a fraud detection model on their combined transaction history. SMPC enables joint ML training while each bank's customer data stays completely private and local.

The Solution

How SMPC Works

Secure Multi-Party Computation (SMPC) allows multiple parties to jointly compute a function over private inputs — while revealing nothing but the final output.

Instead of sharing data, each party shares cryptographic "shares" of their data using Shamir's Secret Sharing. These shares are individually meaningless but collectively encode the data. All computation happens on the shares.

f(x₁, x₂, ..., xₙ) = result
─────────────────────────
Party 1 learns: result only
Party 2 learns: result only
No party learns: others' inputs

This is information-theoretically secure — even an adversary with unlimited computing power who holds k-1 shares learns nothing about the secret.

01

Secret Sharing (Shamir's Scheme)

Each party splits private data into n shares using a random polynomial of degree k-1 over finite field GF(p). Share i = f(i).

02

Share Distribution

Each party sends one share to each of n cloud nodes. No single node holds all shares. Threshold k shares are required to reconstruct.

03

Secure Computation (BGW Protocol)

Nodes compute on shares. Addition is free. Multiplication uses pre-computed Beaver triples — one communication round per multiply.

04

Output Reconstruction

Any k nodes use Lagrange interpolation over GF(p) to reconstruct the final result — revealed only to authorized parties.

Technology Stack

Project Implementation

This project implements a full-stack privacy-preserving computation system — from the cryptographic backend to a secure web interface with multi-factor authentication and role-based access control.

This Flask application implements all modern web security practices: rate limiting, MFA/TOTP, CSRF protection, bcrypt password hashing, session rotation, RBAC, secure cookies, security logging — demonstrating both cryptographic and application-level security.
